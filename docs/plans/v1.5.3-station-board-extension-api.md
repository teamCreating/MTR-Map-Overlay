# 1.5.3 准备：固定站点到站板与统一地图扩展 API

Codex，2026-10-25。基线 main `bf264e3`。**这是源码核对后的设计与验收计划，尚未实现或发布。** 目标版本为1.5.3，本轮不改已发布1.5.2的二进制、标签和版本属性；进入实现时再统一切换双分支版本。

## 1. 本版范围

1. 站点默认折叠；点击站点后展开并固定信息面板，鼠标移开不消失。展开后查看该站各线路、方向/站台的下一班车ETA。
2. ETA复用MTR/TSC生成给PIDS的原生到站数据。提供同一份只读到站板给内置界面及扩展调用，不再实现预测、制动或时刻表模拟。
3. 第三方通过统一API声明线路显示区段和样式，例如确认导航后只显示实际乘车段。Overlay不监听特定导航模组的事件，不加入Navigation/howtogo专用适配器。
4. 保留全图列车同步、纯2D和现有六平台目标。此次恢复的是**站点ETA**，不恢复列车悬停ETA/下一站距离的暂停草稿。

统一接口的草案见 [overlay-api-v1-draft.md](../api/overlay-api-v1-draft.md)。接口名称尚未冻结，不能视为已有可调用API。

### 原生数据能复用什么，不能直接保证什么

- `ArrivalsCacheClient`是3秒刷新缓存，`ArrivalsCacheServer`为1秒缓存；初次读取可能仅登记请求并返回当前空缓存，不代表已经确认“无班次”。
- `PacketFetchArrivals.runServer`使用玩家的serverLevel，不能查询玩家在主世界时地图正在查看的其他维度。
- 服务端缓存构造请求传入 `10, -1`。Core按关联siding收集、排序并限制结果；这不是按线路公平取一条。忙线路可能占满候选，不能将缺失线路解释为当天停运。
- 原生getArrival/getDeparture已包含预测偏差，不应再次叠加getDeviation。getRealtime=false是计划班次，不等于数据损坏。
- 原生PIDS的ETA格式化使用服务端时钟偏移。Overlay应保留原始时间、采样时间和新鲜度，不能拿客户端未经校准的系统时间直接相减。
- ArrivalResponse不提供可普遍唯一关联实际车辆与停站occurrence的完整身份；本站到站板不需要先解决车体关联，不能借机把站点ETA贴到某列地图车上。

## 3. 站点交互与到站板

### 3.1 固定与折叠规则

状态为 `NONE / PINNED_COLLAPSED / PINNED_EXPANDED`。未选中时仅有原来紧凑站点标记/悬停，ETA默认不订阅。**单击站点一次即进入PINNED_EXPANDED**，固定在屏幕边缘，不跟随鼠标；移开鼠标、拖动地图或站点移出视口均不收起。

- 标题折叠按钮进入PINNED_COLLAPSED，仅显示站名和简要信息，释放内置ETA兴趣；再次展开恢复请求。
- 点击另一站替换当前面板；点击同一站只聚焦，不造成闪烁/重复订阅。空白区域仍可平移地图，不取消固定。
- 关闭按钮/首次Esc关闭面板，下一次Esc才交给地图。地图关闭、断线或切换查看维度时清理面板和未完成请求；重新打开默认折叠。
- 拖动不能误触站点：在按下/释放之间判断位移阈值，面板控件先消费输入，再判断站点，再交给宿主。Xaero现有click hook仅处理两个开关，须补共享命中及按下/释放逻辑；JM5/6各有宿主桥。
- 面板是GUI坐标层，固定宽度/小屏自适应并可滚动；内部点击、滚轮不穿透地图。只消费站点与面板命中的输入，不破坏宿主路标/平移。

### 3.2 分组与状态

按线路分标题，每条线路下按**目的地方向和站台**显示下一班：`线路色/名称 → 终点 · 站台 · ETA`。相同颜色/名称不合并；对向站台、不同分支目的地不压成一条。初版保守保留不同站台的行，不猜测它们是同一班车。

- 以原生route/platform ID、destination及环线信息建立服务分组；若站台反复出现而原生结果不能消歧，明确标记，不能伪造停站索引。
- 到站前倒计时；arrival≤now<departure显示“已到站”；终到班次标“终到”。API保留终到标志，供导航消费者自行排除不可登乘班次。地图默认是**到站板**，不把发车倒计时冒充到达ETA。
- 区分实时/计划、加载中、有效空结果、查询受限/覆盖不全、数据过期、服务端不支持、站点已删除。未知/缺失不显示0秒；到站时间过去也不能无限保持“即将到达”。
- 同站所有线路都有元数据行；没有候选时显示“暂无可用预测”，仅在完成查询且覆盖充分时显示窗口内无班次。数量上限触发时必须标覆盖不全。

### 3.3 数据链路

`站点选择 → StationBoardService兴趣 → stationId在权威维度解析站台 → Simulator线程执行原生ArrivalsRequest → 统一不可变BoardSnapshot → UI/API消费者`

优先复用原生操作/预测逻辑，不调用HTTP、不抓网页、不要求世界里放PIDS。完整远程站点由Overlay新的服务端能力支持；纯客户端兼容回退可使用原生PIDS请求，但仅针对玩家维度，明确标注范围/完整性，不能假装拥有全图能力。

服务端在目标Simulator线程读取station.savedRails等现有关系，先解析ID再查询，不在渲染线程或网络回调中遍历模拟对象。业务只筛选/分组原生结果，不新增预测算法。结果复制完成后才切回MC网络线程发送。

初步预算为选中站1Hz更新、客户端本地显示倒计时；同站同维度多观看者复用同一采集/编码。只对实际兴趣查询，不广播全世界所有车站ETA。面板折叠停止自己的兴趣，外部合法订阅按各自句柄继续，最后订阅释放后停止采集。

候选数量采用有界扩大：不足以覆盖已知服务组时提高原生count到配置上限；达到上限仍缺组则返回LIMITED，而不是自行计算下一班。批量站台数、总候选、每玩家兴趣数、服务端待办队列和TTL均必须有界；P0基准后确定默认值。候选上限只能限制结果量，**不能宣称它自动限制Core内部扫描时间**。

响应携带serverEpoch、dimension、stationId、queryGeneration、sampledAt、serverNow及覆盖状态。客户端用单调时间推进收到的serverNow，RTT校正和误差另记录；重开/切服/切维度后的旧响应不得安装。

## 4. 第三方地图API的边界

### 4.1 三个门面，同一身份模型

1. **MapReadApi**：只读站/台/路线/轨道目录和几何，带数据来源、revision、新鲜度、完整性。替代反射内部MapDataCache，不公开可修改数组或Core对象。
2. **MapViewApi**：按所有者创建可关闭的视图会话，原子提交区段选择、未选内容隐藏/淡化和声明式样式。只改变显示，不删除或改写底层地图缓存。
3. **StationBoardApi**：订阅同一StationBoardService的只读结果。内置面板是第一个消费者；将来其他PIDS/HUD可以使用同源结果，但不强制改写原生MTR PIDS实现，也不新增HTTP服务。

API为Java17、无Minecraft/NeoForge/Fabric/MTR/Xaero/JourneyMap类型的契约。实施时单独提供compileOnly API产物，由Overlay在运行时提供同一套类；调用方不把它再次shade进模组。loader/MC差异都在内部适配器。根包固定 `io.github.teamcreating.mtrmap.api`。

### 4.2 “只显示乘坐的一段”必须有真实区段

当前MapRoute.trackIds经过distinct，Stop只含坐标/站名/目的地；collectDepotPath还会按展示染色分段并用平台交集选择serving route。它们是绘制缓存，**不是可用于导航的有序线路契约**。

新增目录需要原生station/platform/route ID和停站occurrence，另提供原生路径片段引用。将路线语义与物理几何分离：

- 普通调用者提交 `RouteSection(routeId, fromStopOccurrence, toStopOccurrence, optionalPathVariant)`；起止包含平台ID，重复停站按本API目录的序号消歧。
- 几何已有的调用者提交 `RailSpan(railId, startFraction, endFraction)`，支持半条轨道。fraction是**原生弧长的归一化距离**，不是屏幕距离或Bezier参数；方向允许反向。
- 不通过站名、颜色或直线裁剪猜路线，不在客户端运行铁路寻路/模拟。只引用或截取已经存在的Core原生路径/几何。
- route→路径关联以原生停站序列和实际path variant核验；多个depot路径、重复站台、共站同路线和折返可能不唯一。解析结果必须区分EXACT/AMBIGUOUS/UNAVAILABLE，歧义时给候选或拒绝，不能默认选第一条。
- 外部模组的revision和stopIndex不一定与Overlay同义。调用方先取得本API目录，映射ID/occurrence；不能直接比较不同模组的拓扑hash。

第三方可以设置未选区段HIDE，获得类似公共交通导航的地图；同一条长线路的前后未乘段也隐藏。站台、换乘点、轨道底衬和白块都按一致区段处理，共线未选色带不残留。外部可声明有限矩形裁剪范围；精确导航仍以区段选择为主。

### 4.3 数据扩展与兼容

先保留静态v8和全图列车v1，新增可选catalog/route-section及station-arrivals能力与独立协议。目录带baseStaticRevision，引用已有rail几何，不重复发送全套轨道采样。客户端在相关静态快照未就绪时等候/请求更新，不安装错代区段。

旧服务端仍可使用已知v8的整线/精确rail span显示API；原生路径解析、完整站点ETA不可用时返回能力/状态。新能力不会为了站点功能回退或改造已完成的全图列车同步。

**首个实现门**：实际依赖中确认原生路径与route/stop occurrence能够可靠对应。先实现并测试精确rail spans，再开放已通过夹具的RouteSection解析；不能只交付routeId过滤却声称支持任意乘车区段。

## 5. 绘制、生命周期与开销

- 全局enabled和用户图层开关是硬开关。第三方会话不偷偷改配置文件，也不改线路颜色/路线资源等MTR原始数据。
- API样式为颜色、透明度、相对宽度、描边和有限pattern；不公开逐帧任意回调/宿主VertexConsumer。保持世界缩放规则和纯2D，白块沿原有路径相位连续。
- 多个FOCUS会话不直接求交：由优先级和确定的激活次序选择一个控制底图范围；DECORATION只叠加样式。句柄close只撤销自己的状态，恢复下一有效会话/普通地图。
- 导航会话可跨地图开关保持，取消导航/close后恢复全图；关闭地图仍释放内置UI的ETA兴趣。断线/换世界全部会话失效。面板自身每次打开默认折叠，与第三方导航生命周期分离。
- 选择/样式/几何修订纳入PlanarMapCache失效身份。只在提交或静态拓扑变化时解析区段/构建索引；逐帧绘制只处理视口候选，禁止每帧调用第三方或全网复制几何。
- 渲染选择不改变TSC全图车辆网络成员。当前列车定义没有可靠routeId，API v1只允许保留/隐藏车层，不承诺按routeName/颜色筛选所属车辆。
- 声明式样式最多增加有限图元/合批变化；区段解析和ETA查询都有新成本。缓存命中、候选数/排序、序列化字节、Simulator耗时和客户端帧耗时需分别测量，不能直接宣称此次API零开销。
