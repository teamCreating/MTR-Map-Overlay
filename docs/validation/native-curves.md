# 原生曲线与细线边缘验证

Codex，2026-10-21 13:34（Asia/Taipei）。mod 版本仍为 **1.5.2**；纯 2D 不变。静态快照升级到 **v8 / `_v8` 通道**，服务器与客户端需同时更新，旧通道不会把新增字段当作 v7 读取。

## 根因与实现

上一轮只修复物理轨道接头。固定每 8 格、最多 256 点的 TRACK 折线仍是绘制源，放大后会直接暴露直线段；端头 miter 不能恢复丢失的曲率。

- 每段轨道同步原生端点、角度、形状、竖曲线/侧倾参数和权威包围盒。保留粗 XYZ 点供现有拓扑/拾取使用，但绘制直接调用 MTR RailMath 的解析位置函数；不向粗折线拟合另一个样条。
- 按屏幕误差目标 0.08 GUI 像素递归细分；检测中点及两个四分点，避免漏掉中点恰好落在弦上的 S 弯。端点法向由原生曲线短区间切向求取，接头也使用原生切向。
- 真实 Core 里程作为色块相位来源，缩放改变点数不会改变轨道长度/相位。直线可只有两个端点。每轨道有 8192 段、20 层保护上限；目标误差不是无限精度保证。
- 灰色轨道/线路底衬的两侧新增 0.35 GUI 像素的 alpha 过渡带，外侧顶点透明、内侧不透明；两种地图都按顶点 alpha 提交，处理细线像素阶梯。它是几何边缘过渡，不是开启全局 MSAA。
- 曲线网格按向上取整的 2 倍缩放等级缓存，等级内的平滑 zoom 复用曲线，线宽仍按实际 scale 重建；先剔除不可见轨道，车辆更新不重新计算曲线。每 host 额外最多保留 maxQuads 个曲线点，只留当前 guard 视口用到的网格，切换快照/清理时释放。
- Core RailMath 构造器会用 0.1 格步长扫描包围盒。服务端导出直接复用只读数学对象；客户端 MapRailMath 仅将这个构造期扫描限制到约 256 步，位置/长度解析函数不变，剔除使用服务端导出的原包围盒。避免长直线仅为初始化包围盒就扫描上亿次。
- 快照 hash 新增角度、形状、竖曲线半径及 transportMode；同一端点 ID 的曲线修改会重新同步。

## 数值与自动化验证

61 项普通测试通过，生成 TestWorld 用例 1 项跳过；NeoForge/Fabric 构建通过。Fabric 保留既有可选 Xaero 方法重映射警告，本轮未启动 Fabric。

NativeRailCurveTest 将解码曲线与原生 RailMath 的 1001 个位置比较，覆盖 QUADRATIC / TWO_RADII / CABLE、反向端点、负高度、远坐标、侧倾与竖曲线；XYZ 误差小于 1e-8。另验证原生参数通过全网 codec 往返、长直线两点、LOD/车辆更新复用、alpha 方向和面剔除绕序、非法枚举拒绝。
